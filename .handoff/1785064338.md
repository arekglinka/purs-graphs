IMPORTANT DECISIONS
-------------------
- spago 0.93+ workspaces (multi-package monorepo) — modern PureScript best practice; NOT legacy single-package spago; NOT purescript-native (still too new)
- purs-backend-es as backend (new PureScript JS backend, replaces legacy purs compile output)
- Vite 5 for HMR — NOT webpack (sub-second rebuilds, simpler config)
- AL2023 base (public.ecr.aws/lambda/nodejs:20) chosen over Node slim to match handoff context patterns; gives Lambda-target parity if ever needed
- GitHub Releases for FFI bindings — NOT npm (enterprise-friendly, no npm tokens needed, forks host their own releases)
- Bindings kept as npm peer-deps (NOT vendored into purs packages) — consumers dedupe; examples install dagre/@viz-js/viz themselves
- podman run --entrypoint '[]' in build-devcontainer.sh — Lambda Node base uses CMD not blocking ENTRYPOINT, but the pattern is safer and matches the originating project's hard-won lesson
- Three CI workflows split by concern: ci.yml (PR builds), release.yml (publish artifacts), devcontainer.yml (publish image) — matches the originating project's successful pattern
- Three-tag image publishing (sha/latest/dev-YYYYMMDD) — immutable + mutable + date-stamped; matches originating project
- No postCreateCommand in devcontainer.json — prebuilt image workflow bakes everything in
